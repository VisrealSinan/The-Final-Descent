# Hackathon Official Rules

Official rules for Andrew, Davey and Han’s hackathon. **Humans define the game; Dots help bring it to life.**

# Objective and timing

- **Goal:** each participant creates one playable video game.

- **Time limit:** seven consecutive days, starting at that participant’s next GPT reset.

- **Rolling starts:** agreed by Andrew, Davey and Han; participants do not need to start together.

| Participant | Start date |
| - | - |
| Davey | November 12, 2026 |
| Andrew | November 13, 2026 |
| Han | November 16, 2026 |

Each participant’s finish is seven consecutive days after their own start.

- **Genre:** open.

- **Platform:** open, including browser, desktop or mobile.

- **Art style and complexity:** open, including 2D or 3D.

- **Required outcome:** a playable game.

# AI tools

- Any AI model may be used, including ChatGPT, Claude, local and open-source models.

- AI asset and music tools are allowed. Examples include Tripo, Mureka and Suno; this is not an exhaustive list.

# Repository and README

Each game’s repository must include:

- The hackathon rules document.

- A README listing the tools used.

- Instructions in the README explaining how to play.

A tool-by-tool mapping to individual assets, code or uses is **not required**.

# Human and Dot roles

- Humans are the idea engine. Dots may help refine ideas and bring them to life.

- Dots may lead development execution, including coordinating tasks and managing GitHub.

- Dots may assist with or fully operate tools, including the game engine.

- Dots may not take a broad idea and independently turn it into a finished project. For example, “Make an RTS set in colonial times and tell me when it is finished” is outside the allowed scope.

# Overnight Dot work

- Overnight work must be limited to issues the human has defined and approved.

- Dots may make routine implementation decisions and use the tools they would normally use during the day, within the issue’s scope.

- Supporting tasks reasonably necessary to complete the issue are allowed.

- Unrelated features or creative work are not allowed merely because the Dot thinks they would be useful.

- Major unresolved design decisions and any expansion beyond the issue must wait for the human’s decision.

## Examples

- “Design sprites as needed to fill this house’s interior” permits creating the necessary sprites.

- “Implement the damage calculations we designed today” permits the code and tests needed for those calculations. It does not permit independently deciding to create a new sprite.

**The human defines what the team is making; the Dot can work out how to complete the agreed task.**
